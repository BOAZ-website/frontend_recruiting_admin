# BOAZ 서류 평가

BOAZ 관리자 콘솔([frontend_admin](https://github.com/BOAZ-website/frontend_admin))이 완성되기 전까지 서류 평가만 따로 배포해 쓰기 위한 화면입니다. frontend_admin의 서류 평가 화면과 로그인 화면을 가져와, 지금 운영 중인 백엔드([backend](https://github.com/BOAZ-website/backend) `main` 브랜치)의 API에 연결했습니다.

관리자 콘솔이 완성되면 이 저장소는 쓰지 않습니다.

## 들어 있는 기능

- 로그인과 로그아웃 (`POST /api/v1/auth/admin/login`, `/refresh`, `/logout`)
- 전체 지원 현황: 임시저장을 포함한 지원서 목록과 지원서 상세
- 부문별 서류 평가: 개인 평가 저장, 운영진 평가 현황, 면접 질문, 최종 평가 변경
- 모집 공고 선택: 진행 중인 공고를 먼저 보여 줍니다.

합격자 부원 등록과 권한 관리 같은 나머지 관리자 기능은 넣지 않았습니다.

## 권한

권한 판단은 백엔드 `main` 브랜치 규칙을 따릅니다. 백엔드 `dev`의 새 권한 체계(권한 표)는 쓰지 않습니다.

| 계정               | 볼 수 있는 지원서 | 최종 평가 변경 |
| ------------------ | ----------------- | -------------- |
| 차기대표진 (SUPER) | 전 부문           | 전 부문        |
| 대표진 (SUPER)     | 본인 부문         | 본인 부문      |
| 그 밖의 팀 (TEAM)  | 본인 부문         | 불가           |

최종 평가는 `role`이 SUPER이면서 소속이 대표진·차기대표진인 계정만 바꿉니다. SUPER라도 다른 팀이거나, 소속이 대표진·차기대표진이라도 TEAM이면 본인 부문만 보고 최종 평가는 바꾸지 못합니다.

화면은 이 규칙에 맞춰 메뉴와 버튼을 보여 주고, 실제 검사는 백엔드가 합니다.

- 왼쪽 메뉴의 서류 평가에는 볼 수 있는 부문만 나옵니다. 본인 부문 계정은 "전체 지원 현황"과 본인 부문 하나, 메뉴가 두 개입니다.
- 본인 부문 계정의 전체 지원 현황 목록에는 본인 부문의 제출 완료 지원서만 나옵니다. 백엔드는 임시저장도 돌려주지만 목록에서 뺍니다. 그래서 제출 상태·부문 필터와 부문·상태 열도 없습니다.
- 위쪽 요약은 계정과 상관없이 같은 여섯 칸입니다. 본인 부문 계정은 본인 부문의 지원자 수·제출 완료·임시저장을 세고, 볼 수 없는 부문 칸에는 `-`를 둡니다.

## 실행

Node 버전은 `.nvmrc`를 따릅니다.

```bash
npm ci
cp .env.example .env.local   # VITE_API_BASE_URL을 채웁니다
npm run dev
```

| 명령                   | 하는 일                     |
| ---------------------- | --------------------------- |
| `npm run dev`          | 개발 서버                   |
| `npm run build`        | 타입 체크 후 빌드 (`dist/`) |
| `npm run check-types`  | 타입 체크                   |
| `npm run lint`         | ESLint                      |
| `npm run format:check` | Prettier 형식 검사          |

## 배포할 때 확인할 것

- 도메인의 루트(`/`)에 올리도록 빌드합니다. 하위 경로(예: `/recruit/`)에 올리면 JS·CSS 경로가 맞지 않아 화면이 뜨지 않습니다.
- `VITE_API_BASE_URL`에 운영 API 주소를 넣고 빌드합니다.
- 이 앱의 브라우저 저장소 키는 `boaz_recruit_*`로 시작합니다. 관리자 콘솔과 같은 주소에 올리면 저장소를 함께 쓰게 됩니다.
- 백엔드 `main`의 CORS는 `www`·`dev`·`api`·`admin.bigdataboaz.com`만 허용합니다. 다른 주소에 올리면 백엔드 설정을 바꿔 다시 배포해야 합니다.
- 로그인 유지에 쓰는 Refresh Token 쿠키는 `bigdataboaz.com` 도메인, `SameSite=Strict`입니다. `bigdataboaz.com`의 하위 주소에서만 새로고침 뒤 로그인이 유지됩니다.
- Access Token은 브라우저 메모리에만 두고 저장소(localStorage)에 넣지 않습니다.
